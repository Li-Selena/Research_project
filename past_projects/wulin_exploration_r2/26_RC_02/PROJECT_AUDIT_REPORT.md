# 26_RC_02 项目审计与当前状态

审计基于当前源码，不作为历史版本记录。坐标与接口的权威定义见 `COORDINATE_SYSTEM.md` 和 `ROBOT_USB_CONTROL_PROTOCOL.md`。

## 项目结构

这是 STM32H723 + FreeRTOS 的 Robocon 机器人下位机工程，主要模块包括：

- `Applications/Task`：CAN、控制、INS、USB/USART 收发任务。
- `Applications/App_user`：八种底盘速度/位置模式、世界/机器人坐标转换和 yaw 闭环。
- `Applications/R2_user`：上下台阶、激光测距和 yaw 自动整定。
- `Components/Algorithm`：麦轮运动学、里程计、S 曲线、机械臂 IK、导航数学。
- `Components/Controller`：PID 和机构控制器。
- `Components/Device`：IMU、机械臂工具等设备抽象。
- `PC_USB_Serial_Tool`：协议打包、串口 shell、状态解析和流程记录。

## 当前统一约定

- 全局右手坐标系：X 前、Y 左、Z 上、yaw 逆时针为正。
- 麦轮运动学和编码器正运动学使用物理轮速向前为正，右侧电机的安装反向只在 CAN/编码器边界处理。
- HWT605 原始安装轴 X 右、Y 前、Z 上，在 `INS_Task` 入口转换一次；控制、导航和状态均使用统一坐标。
- 机械臂目标以机械臂基座为原点，方向同样是 X 前、Y 左、Z 上。
- 攀爬小驱动轮正位移表示前进；立杆范围为 -30..260 mm。
- 综合状态协议版本为 4，上位机解析器会明确输出 `FLU` 坐标信息。

## 任务与控制链路

控制定时中断只发送任务通知，运动学、里程计和控制计算在任务上下文运行。底盘每轮先更新 IMU yaw，再将四轮编码器增量转换为统一机器人系位移并积分到世界系，随后计算速度或位置控制输出。

USB 参数命令先检查 DATA 长度，再读取四个 float；控制源切换集中经过统一接口。速度控制有看门狗，状态请求通过队列发送，避免请求覆盖。USART 遥控帧包含 40 字节数据，底盘和机械臂字段与 USB 使用相同坐标语义。

## 机构现状

机械臂采用三自由度安全 IK，区分不可达、关节范围、工作空间边界和锁平面等结果；失效目标不会直接覆盖最后有效目标。工具机构分别维护夹爪和吸盘状态。

上台阶正式流程为 14 步，下台阶为 15 步。自动流程在进入正式动作前执行激光门控和底盘前向接近；立杆待机位为 -30 mm。流程的可读镜像在两个 action-sequence YAML 文件中，源码表仍是运行时真值。

## 本轮一致性修订

- 新增统一坐标头和总说明，将底盘 API、运动学、里程计、INS、自动整定路径、台阶底盘动作和协议解释迁移到 FLU。
- 协议版本从 3 升到 4，状态布局未改变，X/Y 字段语义按新版本解释。
- 更新上位机命令说明和状态解析，修正 -10 mm 与 -30 mm、下台阶接近方向以及已变化的流程步数。
- 清理源码中乱码、问号占位和失真的注释，并把相关文本统一为 UTF-8/LF。
- 统一轮径常量，补充坐标变换与麦轮正反解测试。

## 验证边界

仓库可执行主机侧 Python 校验和纯数学 C 测试。完整固件仍需在安装了 ARM 编译器和 STM32 工程依赖的环境中编译，并在低输出条件下逐轴确认电机安装方向、IMU 安装矩阵和自动台阶门控。坐标迁移保留了旧命令的实际运动方向，但任何外部脚本都必须按协议版本 4 更新字段解释。
